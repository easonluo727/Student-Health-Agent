## 一年的看病花费（`plan_db.year`）

- 次数来自问卷（`bank.VISIT_FIELDS`：题号 → 场景），由 `hooks.py` 传给 `compare_plans`，模型不能传。模型选了某个场景但用户没给次数，就按 1 次算并标为 `assumed`；用户填 0 就去掉这个场景；用户给了次数但模型没选的场景照样计入。推荐计划时，Python 会自动发表单，问模型所选场景还没问过的次数。
- 每一次就诊按顺序计价，并扣减剩下的 deductible，所以 deductible 全年只付一次。例子：UC SHIP Network 档做 3 次 MRI，第一次是 $400 deductible 加上剩下 $600 的 20%，共 $520，后两次各 $200，合计 `1 x $520.00 + 2 x $200.00 = $920.00`。
- 合计受该档 OOP max 封顶。OOP max 和 deductible 取自保单库的 plan_level 行，都带页码和原文。
- 有多个档位的计划（UC SHIP）用这些就诊下最便宜的那个有价格的档，并在 `tier_note` 里说明。
- 原来"deductible 未满 / 已满"两种情况去掉了：给明年选计划时，一年从 deductible 未满开始算才对。

## 排名公式（`plan_db.rank_plans`）

- 用户没给任何优先级打分：按 `year_total`（年保费 + 看病花费）排名；缺保费输入时只按看病花费排名，并注明不能据此推荐（`visits_only`）。
- 用户打了分（`weighted_score`）：
  - 每个优先级上，最好的计划得 100 分，最差的得 0 分，中间按金额线性插值。各优先级比较的数字：保费比一年保费，看病花费比上面算出的全年看病花费，坏年份保障比 OOP max。
  - 权重 = 打分 − 1。打 1 分（Don't care）的权重为 0；没打分的按 3 分算，权重为 2。
  - 总分 = 各优先级得分的加权平均，满分 100。每个计划都列出每一项贡献了多少分，各项相加正好等于总分。
  - "保留医生"暂不计分，并说明原因：数据库还查不了医生在不在网络里。某个优先级只要有一个计划的数字未知，这一项就不计分。
  - 月保费超过预算的计划排在预算内的计划后面。分数相同时，年总花费低的排前面。
- 结果里的 `ranking.summary` 用一句话说明公式，`ranking.factors` 列出每个优先级的打分、权重，以及是否计分。前端 Arena 面板有一节 "How this ranking works"。

## Arena 面板（`workflow/arena_report.py`）

- `compare_plans` 算完、且不缺输入时，`server.py` 发出 `report` 事件，格式见 `docs/frontend-protocol.md`（Report）。
- 三个视图（tab）：你的预计年度、健康年（只有保费）、坏年份（保费加 OOP max）。
- 对比表包括：排名和分数、每个优先级的得分、每类就诊（次数 × 单次费用、用了哪条福利规则、保单页码和原文）、全年看病花费、deductible、OOP max、计价档位。
- 模型在聊天里只说排第一的计划和原因，不再重复整张表。
